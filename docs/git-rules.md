# Git運用ルール

## リポジトリの初期化

クローン直後（または新規作成直後）に /git:init を実行する。git の初期化と、push 前の機密情報チェック（`.claude/hooks/pre-push`）の登録が行われる。

## 基本方針

- `main` への直接コミット・プッシュは禁止（`/git:push` コマンドでもブロックされる）
- プッシュは生の `git push` ではなく必ず `/git:push` コマンドを使う
- **機能追加** は `feature/<機能名>` ブランチで作業し、PR 経由で main へマージする
- **バグ修正** は `fix/<バグ名>` ブランチで作業し、PR 経由で main へマージする

## コミット & プッシュの手順

### 機能追加

1. feature ブランチを作成して作業する
   ```
   /git:branch feature/<機能名>
   ```

2. コミット・プッシュは `/git:push` で行う（生の `git push` は使わない）
   ```
   /git:push "feat: 変更内容の説明"
   ```
   - `/git:push` は追跡済みファイルのみ自動でステージングする。新規ファイルは事前に `git add <ファイル>` しておくこと

3. プッシュ後、`/git:pr` で PR を作成する

4. CI の成功を確認して `/git:merge` で main へマージする（CI が失敗している状態ではマージしない）

### バグ修正

1. fix ブランチを作成して作業する
   ```
   /git:branch fix/<バグ名>
   ```

2. コミット・プッシュは `/git:push` で行う（生の `git push` は使わない）
   ```
   /git:push "fix: 変更内容の説明"
   ```

3. プッシュ後、`/git:pr` で PR を作成し、CI の成功を確認して `/git:merge` でマージする

## ブランチ運用

- `main` ブランチ: 本番相当の安定コード
- `feature/<機能名>`: 機能追加用（PR 経由でマージ）
- `fix/<バグ名>`: バグ修正用（PR 経由でマージ）
- `docs/<ドキュメント名>`: ドキュメント修正用（PR 経由でマージ）

マージ済みのローカルブランチが溜まってきたら `/git:cleanup` で整理する。引数なしで実行すると削除対象の一覧が出るだけで、何も削除されない。

## コミットメッセージ規約

| プレフィックス | 用途 |
|---|---|
| `feat:` | 新機能の追加 |
| `fix:` | バグ修正 |
| `refactor:` | リファクタリング |
| `docs:` | ドキュメント変更 |
| `chore:` | ビルド・設定変更など |

例: `feat: ログイン画面のパスワード再設定リンクを追加`

## 注意事項

- `.env` やシークレット情報を含むファイルは絶対にコミットしない
- `git push --force` は原則禁止（main ブランチへは特に厳禁）
- プッシュ前に `/git:diff` や `/git:status` で変更内容を確認する
