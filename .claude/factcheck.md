# Factcheck — ハルシネーション防止チェックリスト

コードを生成・提案する前に、このファイルを参照してハルシネーションを防ぐこと。

---

## 凡例

| マーク | 意味 |
|--------|------|
| ✅ 確認済 | 実在を一次資料で確認した |
| ⚠️ 要確認 | 未確認。使用前に必ず調べること |
| ❌ 非実在 | 存在しないことが判明（AIのハルシネーション） |
| 📭 出典なし | 一次資料が存在しない（AIの独自ロジック・慣例・推測による実装） |

---

# 1. ライブラリ実在確認

## パッケージ

### 新パッケージ追加時のチェックリスト

- [ ] パッケージレジストリ（NuGet / npm / PyPI等）で実在することを確認した
- [ ] 対象のランタイム・バージョンに対応していることを確認した
- [ ] 週間DL数・最終更新日を確認し、メンテナンスされていることを確認した

## フレームワーク・ランタイム

### API使用前のチェックリスト

- [ ] 公式ドキュメントでクラス名・メソッド名・引数を確認した
- [ ] 対象バージョンで利用可能かを確認した（廃止・追加のバージョン）
- [ ] 名前空間・インポートが正しいか確認した

## フロントエンド（CSS・JS）

### CSS・Web API 使用前のチェックリスト

- [ ] CSS プロパティ・値が実在するか MDN で確認した
- [ ] JS の Web API・組み込みメソッドが実在するか MDN で確認した（非推奨になっていないか）
- [ ] 対象ブラウザでサポートされているか確認した（MDN のブラウザ互換性表 / Can I use）
- [ ] 外部ライブラリの CDN URL・パッケージ名が実在するか確認した

# 2. 捏造禁止ルール

以下の情報をコード・コメント・ドキュメントに記載する場合、**必ず一次資料で裏を取ること。確認できない場合は記載しない。**

## 裏取りが必須な情報の種類

| 種類 | 裏取り方法 |
|------|-----------|
| 日付（リリース日・制定日・更新日等） | 公式サイト・GitHub Releases・パッケージレジストリで確認 |
| 数値（バージョン番号・設定値・統計値等） | 公式ドキュメント・一次資料で確認 |
| 人名・組織名・固有名詞 | 公式サイト・一次資料で確認 |
| APIのパラメータ名・戻り値・シグネチャ | 公式ドキュメントで確認 |
| アルゴリズム・計算式 | 論文・仕様書・公式ドキュメントで確認 |

## 対応方針

| 状況 | 対応 |
|------|------|
| 一次資料で確認できた | 出典URLとともに記述する |
| 確認できない・資料が見つからない | 「出典なし」と明記するか、記述しない |
| AIの記憶のみが根拠 | 記述しない。「確認が必要です」と伝える |

> 「たぶんこうだったはず」はNG。確認できなければ「要確認」または「出典なし」と明記する。

## 記事・コンテンツの偽造禁止

実在しない記事・ニュース・レビュー・レポート等を、あたかも実在するかのように作成・引用・要約しない。特定の記事の内容に言及する場合は、実在と内容を一次資料（該当記事そのもの・公式サイト等）で確認すること。確認できない場合は、記事の存在や内容を断定的に記載せず、「出典が確認できない」旨を明記する。

## ハルシネーションが起きやすいパターン

1. **存在しないパッケージ名** — 名前を微妙に間違えて提案することがある
2. **廃止されたAPI** — バージョンアップで削除されたメソッドを提案することがある
3. **バージョン番号** — 実在しないバージョンを提案することがある
4. **日付・年号** — リリース日や制定年を誤って提案することがある
5. **計算式・アルゴリズム** — 出典のない独自ロジックを既存理論として提示することがある
