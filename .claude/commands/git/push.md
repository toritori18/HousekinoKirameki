コミットメッセージを引数として受け取り、コミット＆プッシュを行います。

まず、未追跡の新規ファイルがないか確認してください。

```powershell
git status --porcelain
```

`??`（未追跡）のファイルがある場合は、その一覧をユーザーに提示し、コミットに含めるべきファイルだけを `git add <ファイル>` でステージングしてください。ログ・一時ファイルなど含めるべきでないファイルは追加せず、必要に応じて `.gitignore` への追加を提案してください。

その上で、以下のスクリプトを実行してください（シークレットチェック（`.env.local` の追跡確認）→ ブランチ名の検査 → マージ済み PR の検査 → 追跡済みファイルの自動ステージング → jev による判定 → コミット → プッシュ（pre-push フック））。

シークレットチェックのあとのブランチ名・マージ済み PR の検査は、ステージ・コミットより前に行い、次の場合はステージ・コミットせずにエラーで止まります。

- `main` 上で実行した場合
- 現在のブランチを head とする PR がマージ済みで、OPEN な PR が無い場合。`/git:branch <新しいブランチ名>` で最新の main から新しいブランチを作り（未コミットの変更はそのまま持っていけます）、そこで `/git:push` し直してください。`gh` が無い・未認証・オフラインで判定できないときは WARNING を出して続行します

プッシュ時は pre-push フック（`.claude/hooks/pre-push`）が機密情報チェックのあとに `/check` 相当（`.claude/commands/check.ps1`）を実行し、失敗すると push をブロックします。

```powershell
.\.claude\commands\git\push.ps1 "$ARGUMENTS"
```

引数が指定されていない場合は、変更内容をもとに適切なコミットメッセージを提案してから実行してください。

## jev による判定

コミットの直前に、`.claude/jev/check-commit.ps1` が jev（型付きの判断を返す API）で次の2点を判定します。詳細は [docs/jev.md](../../../docs/jev.md) を参照してください。

- テスト追加漏れ（`.claude/project.json` の `testing` が定義されているときのみ）
- コミットメッセージの種類（`feat:` など）が変更内容と合っているか

API キー（`TYPESAFE_API_KEY`）が無いプロジェクトでは何も行われません。既定の shadow モードでは記録と1行の通知だけで、コミットは止まりません。enforce モードで指摘があるとコミットせずに終了し（ステージは残ります）、直したうえで再実行するか、`-SkipJev` を付けて判定を行わずに続行します。

```powershell
.\.claude\commands\git\push.ps1 "$ARGUMENTS" -SkipJev
```
